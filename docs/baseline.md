# Базовое решение

Простая цепочка из стандартных шагов Open3D. Она нужна как рабочая отправная точка: конвейер проходит от облака до сцены, которая загружается в Isaac Sim. Качество сцены здесь не оптимизировано.

## Шаги

| Шаг | Как | Параметры (`configs/baseline.yaml`) |
|---|---|---|
| 1. Обрезка | По границам из `manifest.json` | — |
| 2. Выбросы | `remove_statistical_outlier` | 20 соседей, порог 2,0 σ |
| 3. Прореживание | `voxel_down_sample` | 3 см |
| 4. Нормали | `estimate_normals`, каждая развёрнута к ближайшей точке траектории лидара | радиус 10 см, до 30 соседей |
| 5. Поверхность | `create_from_point_cloud_poisson` | глубина 9 |
| 6. Обрезка | Удаляются вершины с наименьшей плотностью точек и всё за габаритом облака | 3% вершин |
| 7. Visual | `simplify_quadric_decimation` | 200 тыс. треугольников |
| 8. Collision | Та же сетка, упрощённая сильнее | 20 тыс. треугольников |
| 9. Экспорт | `pxr` (пакет `usd-core`) | — |

## Результат на тестовой комнате

Геометрия (`tools/quick_eval.py`):

| Проверка | Значение |
|---|---|
| Расстояние от эталона до сетки, медиана / p95 | 0,28 / 1,24 см |
| Доля сетки в пределах 10 см от эталона | 100% |
| Пол держит (лучи вниз по всей комнате) | 97,4% |
| Пол в пятне, где у лидара нет точек | 0% |
| Проём перекрыт | 0% |
| Время | ~8 с |

Физика в Isaac Sim 6.2 (`tools/isaac_physics_test.py`):

| Тест | Результат |
|---|---|
| Пол, позиций без провала | 8 из 10 |
| Препятствия, проникновение ≤ 2 см | 10 из 10 |
| Проезд через проём | проходит |

Обе проваленные позиции пола — в пятне без точек: корпус падает сквозь пол.

Тестовая комната проще сцены хакатона: в ней нет мелких предметов, а почти все поверхности видны лидару. По ней можно проверить окружение и сравнить свои версии, но не судить о прохождении порогов на данных хакатона.

## Результат на сцене A

| Проверка | Значение | Порог |
|---|---|---|
| Сетка в 5 см от эталона, visual / collision | 88,2 / 88,6% | ≥ 92% |
| Эталон → сетка, медиана / p95 | 1,7 / 4,8 см | ≤ 3 / ≤ 10 см |
| Isaac Sim: пол | 8 из 10 | ≥ 9 |
| Isaac Sim: препятствия, макс. проникновение | 10 из 10, 3,2 см | 10, ≤ 3,5 см |
| Isaac Sim: маршруты | 5 из 5 | ≥ 4 |
| Время | ~12 с | — |

Две позиции пола проваливаются на краю увиденного: лидар видел там пол редко, Poisson не построил поверхность, и корпус падает. Лишняя геометрия — плёнки и наплывы Poisson на шумных и задвоенных стенах.

## Технические замечания

- **Poisson в один поток** (`n_threads=1`). В Open3D 0.20 многопоточный вариант падает с ошибкой `Failed to close loop`.
- **Нормали по траектории.** Без этого Poisson в помещении выворачивает стены наизнанку. Ориентация без траектории (`orient_normals_consistent_tangent_plane`) на облаках в миллионы точек работает очень медленно.
- **Коллайдер из треугольников в PhysX односторонний.** Корпус, подошедший к треугольнику с обратной стороны, проходит сквозь него. Если вы строите поверхности сами, следите, куда смотрят нормали.

## Отсечение и восстановление пола

`configs/poc.yaml` включает два этапа после Poisson и до упрощения. Исходные
параметры и поведение `configs/baseline.yaml` сохранены.

1. Удаляются грани, у которых хотя бы одна вершина или центр отстоит от
   подготовленного облака больше чем на `support_distance=0.06` м. Это отсекает
   неподдержанные плёнки, сохраняя поверхности около реальных наблюдений.
2. Почти горизонтальная плоскость пола оценивается детерминированным RANSAC
   по точкам ниже траектории лидара. Пространственные ячейки ограничивают вес
   плотных сканов мебели. Плоскость уточняется по инлайерам в пределах
   `floor_distance=0.04` м.
3. Наблюдения пола объединяются в ячейки по 8 см и триангулируются в XY.
   Треугольники с ребром длиннее `floor_max_edge=1.0` м отклоняются: весь габарит
   помещения или выпуклая оболочка целиком не заливаются. Несколько близких
   возвратов ниже плоскости исключают достройку на наблюдаемом перепаде.
4. Старые горизонтальные грани пола внутри достроенной области заменяются.
   Новые грани направлены вверх для односторонних коллизий PhysX. Стены и мебель
   не заменяются плоскостью пола.

Реконструкция использует только облако, manifest, траекторию и конфигурацию.
GT и позиции проверок загружаются отдельными оценщиками. При недостатке
опорных наблюдений достройка пропускается с причиной в отчёте. Восстанавливается
одна доминирующая плоскость: остальные уровни сохраняются из Poisson. Небольшое
реальное отверстие без наблюдений ниже него нельзя надёжно отличить от пропуска
сканирования; максимальное ребро ограничивает размер такой интерполяции.

### Сравнение геометрии

На Ubuntu x86_64, Python 3.12.13 / Open3D 0.20.0, сцена A; во всех вариантах
одна исходная сетка Poisson, до 200 тыс. visual и 20 тыс. collision-треугольников.
Оценщик и пороги из ветки `feat/baseline` не менялись.

| Вариант | Visual / collision в 5 см, % | Медиана / p95, см |
|---|---|---|
| Бейзлайн | 88,2 / 88,5 | 1,71 / 4,82 |
| Опора 4 см | 97,7 / 98,4 | 1,95 / 5,04 |
| Опора 6 см | 96,7 / 97,8 | 1,72 / 4,83 |
| Опора 8 см | 94,5 / 95,5 | 1,71 / 4,82 |
| Опора 10 см | 93,1 / 94,1 | 1,71 / 4,82 |
| Только достройка пола | 88,7 / 89,2 | 1,71 / 4,72 |
| Опора 6 см + пол | 96,9 / 97,9 | 1,72 / 4,74 |

Выбраны 6 см: относительно более строгого отсечения 4 см лучше сохраняется
полнота, при этом обе сетки проходят порог 92%. Один полный запуск CLI с этой
конфигурацией дал 96,9 / 98,0%, медиану 1,72 см и p95 4,74 см за 25,7 с.
Малая разница с таблицей связана с отдельным запуском Poisson и выборкой оценщика.

Сравнение вариантов можно повторить:

```bash
.venv/bin/python tools/compare_reconstruction.py --data data/scene_a --out out/comparison
```

Скрипт сохраняет `comparison.json` с хешами входов, параметрами и метриками
каждого варианта. Он переиспользует Poisson и экспортирует PLY для эксперимента;
время полного конвейера и USD проверяются отдельным запуском CLI.

На синтетической комнате полный CLI с той же конфигурацией дал медиану / p95
0,19 / 1,18 см вместо 0,28 / 1,25 см. Покрытие пола лучами выросло с 97,3 до
100%, в пятне без точек — с 0 до 100%; перекрытие проёма осталось 0%.
Это геометрическая проверка лучами; физические тесты в Isaac считаются отдельно.
