# Предобученный NKSR: PLY → mesh → Isaac Sim

Статус: согласованное пользователем направление; реализация начата, inference ещё не подтверждён.
Ветка: `feat/denis-nksr-runtime`, база `main@8102044`.

## Цель и границы

Пользователь загружает PLY, указывает единицы и ось, выбирает NKSR и получает
visual/collision mesh, USD и отчёт. Используем опубликованные веса `kitchen-sink`
(`ks`), без обучения на каждой сцене. Poisson и квалифицированный гибрид остаются
отдельными воспроизводимыми режимами. NKSR не становится default до квалификации.
Отсутствующие поверхности нельзя считать достоверно восстановленными только
потому, что сеть построила сетку. Произвольный PLY не получает обещание гарантии.

Код NKSR распространяется под NVIDIA Source Code License: п. 3.3 ограничивает
использование исследованием и оценкой. Веса ks заявлены авторами под CC-BY-SA 4.0.
Текущий scope — исследовательский PoC; коммерческое применение требует отдельного
решения по лицензированию. Уведомления и лицензии сохраняются в контейнере.

## Контракт реализации

1. H33 задаёт лимиты PLY и декларацию; не добавлять независимые копии лимитов.
   Неизвестные единицы/ось требуют уточнения. Нормализованный вход — метры/Z-up.
2. Для ks нужны XYZ и ориентированные нормали. Сохранить корректные входные
   нормали или использовать реальные позиции сенсора. При их отсутствии оценить
   и согласовать нормали, записать метод и неопределённость. Нельзя подставлять
   фиктивную траекторию. Сомнительная ориентация — диагностируемое ограничение.
3. Отдельный GPU runtime: никакой установки CUDA/torch в системный Python Spark.
   Один GPU worker, явные лимиты/timeout/отмена; работающие чужие сервисы не останавливать.
4. Backend возвращает конечные вершины и допустимые треугольники. Пустая сетка,
   NaN, OOM, timeout и отсутствие весов — явная ошибка. Скрытого fallback нет.
5. Переиспользовать текущие collision/USD экспортёры. Цвет переносится отдельно
   и не заменяет проверку геометрии. Chunking/voxel_size фиксировать в отчёте.
6. Отчёт добавляет backend, upstream commit, image digest, SHA256 checkpoint,
   входа, конфига и выходов, preprocessing, время и память. Форматы существующих
   артефактов сохраняются. Проверяем именно тот USD, который отдаёт UI.
7. UI различает «построено» и «проверено». Без независимых B/GT и физики качество
   `not_verified`. Доступность модели сообщает сервер; ошибка видна пользователю.

## Проверки и продвижение

H42: контрольная сфера с известными нормалями, CUDA inference, непустая конечная
сетка; повтор с отключённой сетью и закреплёнными весами. Это проверка runtime,
не доказательство качества комнаты. Сохранить failed попытки и точные версии.

H43/H44: пол/стены/проём, тонкая стенка, неверные/отсутствующие нормали,
NaN/слишком большой/пустой PLY, неизвестные координаты. Существующие нормали
`lidar2sim/normals.py` зависят от траектории — не применять их слепо к кухне.

H47 сравнивает NKSR и закреплённый гибрид на одинаковых development-входах:
mesh→B, completeness, размеры, проёмы и ложные перегородки, время и память.
Порог итоговой приёмки: ≥95% mesh→B в 10 см; completeness median≤3 см,
p95≤10 см; размеры 10/10≤5 см; физика пол 10/10, препятствия 10/10,
маршруты 5/5, проникновение≤2 см. Полная серия 5 повторов A/C и 10M≤1800 с
проводится через H41 после фиксации кандидата. Holdout не используется для настройки.
Если качество хуже, сохраняем экспериментальный режим и результаты, default не меняем.

`My kitchen.ply`: 976350 точек, RGB, нормалей нет; единицы/ось и независимый
эталон пока неизвестны. Исходник находится только в приватном хранилище Spark.
Пока это development-кандидат для исследования, не зачётный тест.
