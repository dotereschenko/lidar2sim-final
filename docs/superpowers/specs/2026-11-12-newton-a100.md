# Real physics on A100 without Isaac RTX

Status: experimental Newton backend enabled on vkteacher; GPU smoke, scene A execution, API and UI replay verified. Route completion remains unachieved (`blocked`).

## Problem and constraints

Isaac Sim 5.1 compatibility checker on vkteacher's A100 failed at
`vkCreateDevice` with `ERROR_INITIALIZATION_FAILED`. The GPU is visible in
the container, but no graphics device was created. Existing route preview
does not calculate contacts and is not a physical simulation.

Keep driver 570.86.10, host services and other users' jobs unchanged. Use only
GPU UUID GPU-c4306a6e-f03f-55fc-3f12-1c427935c5e4, separate Python environment,
four CPU cores and a wall-clock timeout. No automatic CPU fallback. The user service has no verified hard RAM/VRAM cap; restrict this experimental backend to the fixed scene A and one body. Add enforced memory limits before accepting arbitrary meshes.

## First acceptance gate

`tools/newton_smoke.py` runs Newton XPBD on CUDA. A box falling from 2 m must
settle at its half-height of 0.2 m on a plane; recorded contact count must be
positive. A second run without the plane must fall below -50 m after 4 s with
zero contacts. Save GPU identity, package versions and sampled positions.
These controls distinguish physical contact from scripted motion.

## Subsequent integration gates

1. Import the actual reconstructed collision mesh; do not insert a synthetic
   floor to hide missing surfaces. Test floor support, wall blocking and a
   removed-wall negative control. Record input hashes and solver settings.
2. Add a bounded controller, initially using the explicitly labelled simplified
   body. Report reached, blocked, fell or timeout based on measured states.
   Wheel drives require a separate articulated model and validation.
3. Add a separate Newton runner option to the simulation API. Record the engine
   in each result and retain existing provenance/cancellation checks. Do not
   label Newton output Isaac or imply identical physics across solvers.
4. Show measured positions in the existing 3D UI; distinguish real simulation
   replay from route preview. Video rendering is a separate output stage.
5. Enable the UI option only after a real scene A run and API/UI verification.

## Dependency choice

Use `deployment/requirements-newton.txt` in `/home/vkteacher/lidar2sim-newton`.
Newton 1.0 requires Warp >=1.12. Pin the compatible CUDA 12 build instead of
installing the current Isaac Lab default CUDA 13 stack, which requires a newer
driver. Package compatibility must still be established by executing the gate.

Sources: https://github.com/newton-physics/newton/tree/v1.0.0 and
https://github.com/NVIDIA/warp/tree/v1.12.0.
