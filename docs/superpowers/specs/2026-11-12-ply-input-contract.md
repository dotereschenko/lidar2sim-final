# H33: контракт стороннего PLY v1

## Решение

Единый пакетный JSON-контракт задаёт технические лимиты CLI/UI и область
первой версии: статические одноуровневые помещения. Декларация входа —
утверждение оператора, а не измерение качества. Неизвестные единицы/ось/тип
сцены дают needs_metadata; динамика и неподдерживаемый тип дают unsupported.
Даже supported всегда сопровождается quality_status=not_verified.
Статус supported означает соответствие заявленной области, не приёмку меша.

Схема декларации версионирована отдельно от report.json и профиля H26.
Порогов шума/плотности/наблюдаемости пока нет: они явно uncalibrated,
нужны H35/H41. Нельзя подменять их произвольными числами или допусками меша.
До калибровки нельзя объявлять общую гарантию для стороннего PLY.

## Реализация и границы

- Общие лимиты: 512 MiB и 20 млн точек — существующие эксплуатационные
  лимиты UI, не доказательство качества. Минимум четыре точки — прежнее
  условие загрузчика, не достаточность реконструкции.
- CLI загрузки и UI берут лимиты из одного файла. Legacy CLI без manifest
  сохраняет m/Z для совместимости; проверка декларации не считает это
  подтверждёнными метаданными. Для гарантии требуется отдельная декларация.
- CLI проверки декларации и GET /api/input-contract предоставляют общий
  контракт для H34/H40. Они не запускают реконструкцию или физику.
- Реконструктор получает A/траекторию. Проверочные B/GT остаются у оценщика.
- Тяжёлые тесты и артефакты — только на Spark.

## Приёмка изменения

Тесты неизвестных метаданных, неподдержанного типа, недопустимых полей/версии,
отсутствия повышения качества до passed, точных границ ресурсов, общего
контракта в HTTP и CLI. Регрессия существующих входов, отчётов и UI.
Профиль H26 и его YAML не изменяются. Полная автоматическая интеграция
декларации/диагностики в задание — H34/H40; оценка качества — H38/H39/H41.
