# Сцена A и робот в UI

## Использование

Развёрнутый интерфейс: http://127.0.0.1:8768 через SSH-туннель к vkteacher.
В блоке «Сцена A · Робот» выбрать один из пяти маршрутов, старт и цель из его точек.
Нажать «Показать маршрут и робота». Откроется готовая реконструкция A, камера следует за роботом,
стены показаны в срезе 1,6 м. Предпросмотр ускорен в четыре раза и не вычисляет столкновения.
«Остановить предпросмотр» удаляет маршрут и восстанавливает полный вид сцены.

Модель — корпус 40 × 40 × 30 см, масса 20 кг, управление линейной скоростью.
Колёса декоративные: динамики приводов, планировщика и навигационного стека пока нет.
Выбор произвольной точки мышью и запуск на произвольной загруженной сцене пока не реализованы.

## Текущая сцена и проверка

На 2026-11-12 используется исходная A из 248702 точек, с trajectory_A.csv,
а не финальная пара A/B по 750000 точек. NKSR на GPU A100 подготовил задание
`f6fcd63956b140a3ba8de0d1a9f7591e`: 54416 треугольников, общее время 6,06 с,
время NKSR 1,68 с. Качество этой новой сетки и её физика ещё не проверены.

Каталог `/api/simulation-scene` берёт ID из `LIDAR2SIM_SCENE_A_JOB` либо файла
`scene-a-job.txt` в корне checkout. ID должен указывать на завершённое задание.
Маршруты и параметры корпуса берутся из `data/scene_a/test_config.json`.

В Chrome проверено отображение сцены, робота, линии маршрута и конечного статуса
предпросмотра 15,6 / 15,6 м. На vkteacher прошли 28 тестов
`tests/test_simulation_ui.py tests/test_web.py`. Тестовый исполнитель проверяет контракт
процессов и файлов, а не PhysX. Новый режим tools/isaac_record.py пока прошёл только
проверку синтаксиса: доступного совместимого Isaac-хоста нет.

## Подключение физического исполнителя

Spark недоступен. На vkteacher исполнитель не настроен, кнопка Isaac отключена.
Для запуска нужен совместимый хост с Isaac, ffmpeg и общей с web-сервером файловой системой.
Команда задаётся оператором JSON-массивом аргументов, например внутри Isaac-контейнера:

```bash
export LIDAR2SIM_ISAAC_COMMAND='["/isaac-sim/python.sh", "/workspace/lidar2sim/tools/isaac_record.py", "--headless"]'
```

Это пример для соответствующих путей контейнера, а не готовое SSH-подключение к Spark.
Отдельный транспорт копирования заданий и удалённой отмены между vkteacher и Spark
ещё не реализован. Нельзя подставлять простой `ssh` и ожидать работы локальных путей.
После восстановления хоста нужно проверить пути, GPU/renderer, реальный прогон и отмену,
затем включать исполнитель в сервисе.

API добавляет `--scene`, `--config`, `--out`, `--route`, `--start-index`, `--end-index`.
Оно сохраняет снимки USD и конфигурации, разрешает один физический запуск одновременно,
останавливает свою группу процессов по отмене или после 15 минут. При рестарте сервиса
незавершённые записи помечаются ошибкой. Задания автоматически не удаляются.

Исполнитель пишет preview.jpg, overview.png, simulation.mp4 и recording.json.
UI показывает кадр, журнал, историю и видео завершённого прогона. Отчёт должен содержать
SHA256 снимков сцены/конфига, выбранные robot/route/start/end и outcome:
reached, blocked, fell или timeout. Несовпадение запрещает публикацию результата как завершённого.
Статус completed означает наличие записи; только outcome сообщает результат маршрута.
Это демонстрация PhysX, не полная приёмка геометрии и физики.

Архивная запись из docs/img/release-v2/simulation.mp4 показана отдельно и относится
к предыдущей версии A на Spark. Она не подтверждает качество текущей NKSR-сцены.

## Доступ с Mac

На рабочем Mac установлен пользовательский LaunchAgent
`~/Library/LaunchAgents/com.lidar2sim.vkteacher-tunnel.plist`: он поддерживает SSH-туннель
127.0.0.1:8768 → vkteacher:127.0.0.1:8768 и восстанавливает соединение после обрыва.
Остановить его при необходимости:

```bash
launchctl bootout gui/$(id -u) ~/Library/LaunchAgents/com.lidar2sim.vkteacher-tunnel.plist
```

Plane и Graphiti находятся на недоступном Spark; результаты пока сохранены в Git.
