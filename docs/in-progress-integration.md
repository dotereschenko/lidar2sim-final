# Интеграция активных задач PoC

Объединены квалифицированный оценщик Denis и PR #1 (`f17d967`): реконструкция,
защищённое упрощение collision, контракт файлов, единый запуск и замер 10M.
История обеих веток сохранена. Согласование H3 остаётся отдельным решением.

## Полный CPU-прогон и оценка

```bash
.venv/bin/python tools/run_poc.py \
  --data data/scene_ab_candidate --reference-data data/scene_a \
  --scans data/scene_ab_candidate --annotations out/annotations-v1-observed \
  --evaluation-mode b --config configs/poc.yaml --out out/poc-integrated
```

Для повторения только оценки добавить `--reuse`. Вход реконструкции A должен
совпасть по SHA256 с A пакета оценщика. B и GT передаются только оценщику.
`report.json` содержит contract, geometry, dimensions, physics, performance.
Профиль проверяется каноническим валидатором; наличие YAML не означает согласования.
Без обязательных свидетельств или решения H3 нет общего статуса passed.

Без физического runner команда сохраняет physics=not_run и возвращает 1;
ошибка этапа даёт 2 и записывается в отчёт. Геометрический/размерный FAIL
не скрывает факт непроведённой физики. Повторно приложить physics.json можно
только с совпадающими USD/config/profile/кодом физического оценщика и полным
набором тестов. Старые отчёты PR #1 без этих полей требуют повторного запуска.
Обычный прогон A не засчитывает требование времени для 10M.

## Управляемая очередь Isaac

Оператор запускает один runner от своего SSH-аккаунта:

```bash
.venv/bin/python tools/run_poc.py \
  --data data/scene_ab_candidate --reference-data data/scene_a \
  --scans data/scene_ab_candidate --annotations out/annotations-v1-observed \
  --evaluation-mode b --config configs/poc.yaml --out out/poc-integrated --reuse \
  --physics-runner tools/spark_physics_runner.py \
  --runner-arg=--settings --runner-arg=/path/to/operator-spark.json
```

Файл настроек создаётся по `configs/spark.example.json`. Ключи остаются в SSH;
они не копируются в stage или контейнер. Stage приватный (0700). Передаются
только USD, физический конфиг, профиль и код с проверкой SHA256. Контейнер
использует существующий образ, сеть отключена, ресурсы ограничены настройками.

`isaac_slot.py` держит общую flock-блокировку на весь запуск. Если другая
Isaac-сессия работает, новый запуск отклоняется. Все участники передают задания
одному оператору; прямые самостоятельные Docker-запуски обходят кооперативную
блокировку и не входят в этот порядок доступа.

`pause_known_sessions` по умолчанию пуст. В него оператор может включить только
сессии, на временную остановку которых уже получено разрешение владельца.
Auto-remove контейнеры не останавливаются: их нельзя безопасно восстановить.
Список остановленных/восстановленных сессий сохраняется в `slot.json`; при
ошибке задания собственный контейнер удаляется и перечисленные сессии
запускаются обратно. Ошибка восстановления сообщается отдельно.

Оператор выдаёт команде только её physics.json/логи/видео; общий viewer не
является каналом выдачи чужих данных. Расписание и ответственный организатор
ещё должны быть зафиксированы для мероприятия; технический mutex их не заменяет.
