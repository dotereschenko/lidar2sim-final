# Контракт стороннего PLY v1 — H33

Реализация `5dad4e7` прошла на Spark 209 тестов и 185 подпроверок;
см. [запись проверки](https://github.com/dotereschenko/lidar2sim/blob/15766f2fbc7666d757d7ea57dcca0be8bb7f2373/benchmarks/input-contract-v1.json). Новые физические
прогоны не выполнялись: эта задача определяет контракт, а не качество новых сцен.

Источник технических ограничений — `lidar2sim/schemas/input-contract-v1.json`.
CLI загрузки и веб-сервер используют один файл; SHA256 контракта доступен
через `GET /api/input-contract`. Это отдельная версия входного контракта,
профиль качества H26 не меняется.

| Вход / условие | Решение |
|---|---|
| PLY с XYZ, ASCII или binary little/big endian | Чтение существующим Open3D-загрузчиком; содержимое дополнительно проверяется |
| 1–536870912 байт, 4–20000000 точек | Технический диапазон CLI/UI, не гарантия качества |
| Конечные XYZ; при наличии CSV `t,x,y,z`, конечные значения и строго растущее t | Обязательные структурные проверки |
| Единицы m/cm/mm, вертикаль Y/Z | Допустимая декларация; перед CLI реконструкции нужно нормализовать в m/Z |
| Неизвестные единицы, ось или тип сцены | `needs_metadata`, нельзя угадывать масштаб |
| Заявлено статическое одноуровневое помещение | `supported` только по декларации области применения |
| Лестницы/многоуровневость, улица, отдельный объект, динамика | `unsupported` в области этой версии; отдельная квалификация обязательна |
| Недостаточное покрытие критической области | `needs_rescan` после измерения в H34/H36; текущая декларация не диагностирует покрытие |

RGB не является обязательным. Нормали оцениваются конвейером; наличие нормалей
в файле не подтверждает их правильность. Траектория необязательна для запуска,
но отсутствие поз ограничивает выводы о наблюдаемости и ориентации поверхностей.
Координаты облака и траектории должны быть в одной системе. Mesh PLY не
обещает сохранения исходной топологии: реконструктор использует точки.

## Проверка декларации

```sh
uv run --locked --python python3.11 -m lidar2sim.input_contract examples/input-declaration.json
```

Схема: `lidar2sim/schemas/input-declaration-v1.schema.json`. Неизвестное значение
задаётся `null`; неизвестные поля и версии отклоняются. Код выхода 0 означает
соответствие заявленной области, 1 — неизвестные метаданные/неподдержанный тип,
2 — ошибка структуры или чтения. Ни один результат не подтверждает качество
файла или готовность сцены. Это отдельный лёгкий шаг, не реконструкция.

Legacy CLI без manifest сохраняет прежнее предположение m/Z для совместимости.
Для новой процедуры гарантии оно недостаточно: оператор должен предоставить
декларацию. Настройки UI также являются утверждением пользователя, не проверкой
реального масштаба. Передача декларации вместе с заданием и отображение отказов
реализуются Ясином в H34/H40; endpoint уже предоставляет общий контракт.

## Профиль качества и границы обещания

Допустимые диапазоны плотности, шума, доли наблюдаемой поверхности и минимальных
деталей пока **не откалиброваны** для сторонних сцен. В контракте это `null`
и `quality_envelope.status=uncalibrated`. Фиксированные ресурсы взяты из прежнего
UI, минимум точек — из прежнего загрузчика; они не являются такими диапазонами.
Числа появятся после H35/H41 с указанием измерений и версии профиля.

Качество имеет отдельные статусы: `not_verified`, `accepted`, `failed`,
`needs_rescan`. `generated` существующего отчёта означает только построение.
Область/масштаб, независимая геометрия по B или контрольным измерениям,
физика именно данной сцены и робота, хеши выходных файлов должны быть проверены
перед `accepted`. Нельзя получить его по декларации или только по входному A.
Без эталона — `not_verified`; измеренный провал — `failed`; измеренная нехватка
наблюдений — `needs_rescan`. Тайм-аут не равен успешной проверке.

Профиль `configs/acceptance/lidar2sim-rules-v2.yaml` сохраняет исторические
допуски: ≥95% в 10 см от B, медиана ≤3 см, p95 ≤10 см, 10 размеров ≤5 см,
10/10/5 физики с проникновением ≤2 см. Эти пороги подтверждены на A/C и
определённом тестовом корпусе. Они не становятся автоматически подходящими
для другого робота или класса сканов.

## Передача реализации

- H34/H36 (Ясин): диагностика и измеренная наблюдаемость по этому контракту.
- H35 (Денис): независимые реальные данные; H38/H39: оценщики и физика.
- H40 (Ясин): единый маршрут UI с явными состояниями качества.
- H41 (Денис): закрытая квалификация и калибровка диапазонов, затем расширение
  публичной гарантии. Пока её для произвольного PLY нет.
