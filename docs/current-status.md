# Что готово и как запустить

Состояние на 13 ноября 2026 года. В `main` включена ветка
`feat/uploaded-scene-physics` до `a37d2c3`: предобученный NKSR, развёртывание
на A100, маршруты выбранной реконструкции и воспроизведение Newton.
Полный локальный набор тестов прошёл перед объединением.

Ранее в `main` объединены готовые изменения из
`feat/denis-final-prep-validation`, включая предшествующие ветки данных,
оценщика, UI, реконструкции и `feat/final-prep`. Полная история сохранена.
Старые `feat/poc-runtime` и `feat/observed-planar-surfaces` не включены:
их версии отчётности и экспериментальных плоскостей заменены последующими
реализациями. Исходные ветки не удаляются.

## Что работает

| Возможность | Состояние |
|---|---|
| PLY → визуальная сетка, коллизии, USD, отчёт | Работает через CLI |
| Улучшенная реконструкция с опорой на наблюдаемые поверхности | Проверена на A и скрытой C, пять повторов каждой |
| Загрузка PLY, предпросмотр и скачивание результатов через UI | Работает на vkteacher; NKSR GPU и прежние методы |
| Маршрут на выбранной реконструкции → физика → воспроизведение | Newton CUDA на A100; проверен короткий маршрут, модель корпуса на сферических опорах |
| Независимые A/B, скрытая C, 10 размеров, оценщик и сценарий жюри | Реализованы; закрытые данные доступны только оператору |
| Запуск и физические испытания в Isaac на Spark | Есть прежние протоколы; Spark сейчас недоступен |

Квалифицированный вариант: `configs/poc-planar-floor-support.yaml`, исходники
кандидата `05ff87e`, образ
`sha256:69df0342b54ccdbff0042e10331e46f5dd78ca7c08dd0e71f95d4b845a355eb4`.
На каждой сцене во всех пяти повторах пройдены геометрия, размеры обоих мешей
10/10 и физика 10/10 полов, 10/10 препятствий, 5/5 маршрутов.
Ровно 10 млн точек: 147,132 с, пик RSS 2 295 668 736 байт при 4 CPU/16 ГБ.
[Протокол и доказательства](validation/boundary-pad-qualified-2026-11-12.md).

Комментарий `EXPERIMENTAL` в этом YAML относится к моменту его создания.
Файл сохранён побайтно, поскольку его SHA256 закреплён в протоколе приёмки;
актуальный результат квалификации указан выше.

## Установка из main

Нужны Git, uv, Python 3.11 или 3.12. Выполняйте тяжёлые прогоны на сервере,
где достаточно свободного диска. Пример отдельного checkout:

```sh
git clone --branch main https://github.com/dotereschenko/lidar2sim.git
cd lidar2sim
uv sync --locked --python python3.11
```

Системные библиотеки Linux перечислены в
[инструкции участника](participant-release-v2.md). На Apple Silicon при ошибке
импорта `libusb-1.0.0.dylib` потребуется `brew install libusb`.

## Реконструкция своего облака

Для сторонних сканов см. [контракт входа v1](input-contract.md): общий лимит
CLI/UI, явная декларация единиц/оси и границы применимости. Проверка декларации
не подтверждает качество реконструкции.

CLI ожидает XYZ в метрах, Z вверх. Используйте новый каталог результата.
Для скана с известной траекторией:

```sh
uv run --locked --python python3.11 -m lidar2sim \
  --input /path/to/scene.ply \
  --trajectory /path/to/trajectory.csv \
  --config configs/poc-planar-floor-support.yaml \
  --out out/my-scene
```

CSV имеет заголовок `t,x,y,z`; координаты — в той же системе, что и PLY.
Если траектории нет, уберите `--trajectory`. Обработка возможна, но результат
не наследует подтверждение качества прогонов с траекторией. Manifest, если
есть, передаётся через `--manifest /path/to/manifest.json`. GT/B не нужны
реконструктору. Для первого запуска можно использовать `data/scene_a/A.ply`
и `data/scene_a/trajectory_A.csv`: это исторический пример, а не A750000
из последней приёмки.

Результат: `visual.ply`, `collision.ply`, `scene.usd`, `report.json`.
USD содержит статическое окружение с коллизиями. Подвижные двери, механизмы
и физические свойства отдельных объектов автоматически не создаются.
Успешное построение файла не означает успешную независимую оценку.

## Веб-интерфейс

```sh
uv run --locked --python python3.11 -m lidar2sim.web.server
```

Откройте <http://127.0.0.1:8765>, загрузите PLY и при наличии траекторию,
укажите единицы и вертикальную ось. Лимит файла — 512 MiB, облака — 20 млн
точек. Можно посмотреть облако/visual/collision и скачать результаты.
UI также предлагает предобученный NKSR при установленном GPU-окружении.
Рабочий сервер vkteacher доступен через туннель на <http://127.0.0.1:8768>.
[Развёртывание](vkteacher-deployment.md), [NKSR](nksr-ui.md),
[маршрут и физика выбранной сцены](scene-a-simulation.md).
Квалификация прежнего алгоритма на A/C не переносится автоматически на NKSR.

Для UI на Spark запустите сервер из отдельного checkout на свободном порту,
например `--port 8766`, затем на своём компьютере:

```sh
ssh -N -L 8766:127.0.0.1:8766 spark
```

Откройте <http://127.0.0.1:8766>. Нужны настроенные SSH-доступ и сеть/VPN.
UI однопользовательский, без авторизации и квот диска; не выставляйте его
на публичный интерфейс. Задания сохраняются на диске без автоочистки.
[Подробнее об UI](web-ui.md).

## Isaac и оценка

Откройте полученный `scene.usd` в Isaac Sim 6.2. Физические испытания требуют
конфигурации проверок именно этой сцены; координаты тестов A нельзя применять
к произвольному загруженному PLY. Общий Spark использует очередь/guard:
[инструкция оператора](jury-release-v2.md). UI запускает Newton на A100 и воспроизводит измеренные положения корпуса;
это не Isaac и не RTX-видеозапись. Проверка по B остаётся отдельной.
На A100 Isaac Sim не поддерживается; для него нужен совместимый RTX-сервер.

Команда тестов кода из checkout:

```sh
uv run --locked --python python3.11 -m pytest -q
```

Эти тесты не заменяют физические прогоны Isaac.

Перед публикацией `main` полный набор тестов прошёл на Spark за 20,76 с
в закреплённом образе, с исходниками интеграции `882b3ab`, 4 CPU/16 ГБ и без
сети. Код, конфиги и тесты совпадают с квалифицированной веткой; изменена
документация. [Запись проверки](../benchmarks/main-integration.json).
Повторно запускать неизменную серию Isaac для этого объединения не потребовалось.
