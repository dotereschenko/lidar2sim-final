# Lidar2Sim: старт участника

Архив содержит публичный A (750000 точек), траекторию, 10 контрольных размеров, проёмы, маршруты, конфигурацию физики, фиксированный 10M-набор и starter. Метры, Z вверх. B, скрытая C, NVIDIA-ассеты и внутренние отчёты сюда не включены. Реестр всех файлов — SHA256SUMS.

## Проверка и запуск

Нужно: Python 3.11 или 3.12, uv, доступ к PyPI для первой установки. На Linux для Open3D нужны libgl1, libglib2.0-0, libgomp1, libidn2-0, libgfortran5, libegl1. Зависимости закреплены uv.lock. Docker-вариант использует `starter/deployment/Dockerfile.cpu`.

```sh
# После распаковки, из корня архива:
sha256sum -c SHA256SUMS
# macOS: shasum -a 256 -c SHA256SUMS
cd starter
uv sync --locked --python python3.11
uv run --locked --python python3.11 -m lidar2sim \
  --input ../scene_a/scene.ply --manifest ../scene_a/manifest.json \
  --trajectory ../scene_a/trajectory_A.csv --config configs/baseline.yaml --out ../result
uv run --locked --python python3.11 tools/make_example_scene.py ../example_scene.usd
```

Если установлен Python 3.12, замените `python3.11` в командах на `python3.12`. Явный выбор обходит историческую `.python-version` checkout. Результат: visual.ply, collision.ply, scene.usd, report.json. Для улучшенного или детального режима выберите соответствующий YAML. Успешная генерация не означает прохождение метрик и физики.

Для интерфейса: `uv run --locked --python python3.11 -m lidar2sim.web.server`, открыть http://127.0.0.1:8765. Загрузить scene_a/scene.ply и соответствующую trajectory_A.csv. Выбрать baseline, улучшенный Poisson или высокую детализацию.

## Самопроверка и физика

Публичный GT можно собрать отдельно, при соблюдении условий исходного NVIDIA-ассета:

```sh
uv run --locked --python python3.11 tools/fetch_gt.py ../selfcheck
```

Исходный URL и параметры построения записаны в selfcheck/manifest.json; лицензия приведена в fetch_gt.py. GT не подаётся на вход реконструкции. Контрольные размеры и YAML-описания области доступны для самопроверки. Официальная независимая B-метрика считается жюри/ментором по закрытому B и профилю v2; отсутствие B не заменяется GT.

Example_scene.usd и scene.usd передаются ментору для открытия и физического прогона Isaac 6.2 на Spark. Прямые ключи/аккаунты Spark в пакет не входят. Оператор объявляет расписание и канал заявок до старта. В ответ нужны JSON и видео; снимок успешной загрузки USD не заменяет физические тесты.

## Сдача

Передайте версию исходного кода, конфигурацию и четыре выходных файла для A. Реконструкция должна запускаться одной командой по переданному входу: жюри повторит её на A и на скрытой C в изолированном окружении без B/GT и сети. Файлы B/GT, подстановка готового ответа по имени сцены и зависимость от авторского абсолютного пути недопустимы. Входные единицы/ось и hash исходного облака должны отражаться в отчёте.

[Правила](RULES.md): точность ≥95% в 10 см от B; B→mesh median ≤3 см / p95 ≤10 см; 10 размеров ≤5 см; физика 10/10/5, проникновение ≤2 см. Время 10M ≤1800 с на объявленной зачётной машине. Текущая техническая репетиция и её ограничения фиксируются отдельно; заголовок «старт» не является обещанием непроверенного времени 15 мин.
